# 化工知识与计算助手：技术与验证报告

版本：`0.2.0`。修订日期：2026-10-02。

## 1. 实现范围与交付形态

系统提供中文知识问答、常用单位换算、单相恒比热显热计算和稳态无反应混合衡算。资料为 15 张项目自编教学知识卡；比热、密度等工况相关数据须由用户提供，系统未接入真实物性数据库。

本版将 Gradio 页面替换为原生 HTML/CSS/JavaScript 工作台，由 FastAPI/uvicorn 提供本机页面和接口。无需 Node 构建。桌面布局让输入与输出同时可见，长内容在工作区内滚动；结果区的“结论”“过程”“依据”分别展示答复、实际调用和资料。工具数值与模型说明分开展示。

交付包括浏览器工作台、CLI、源码、锁定依赖、配置模板、教学资料、测试、验证记录和运行说明。

## 2. 技术组成与业务流程

| 组件 | 实现 |
| --- | --- |
| Python | 声明支持 `>=3.11,<3.14`；本机运行 Python 3.12 |
| Agent | smolagents `ToolCallingAgent`，每轮独立创建 |
| 模型 | 可配置的 DeepSeek 兼容 OpenAI 接口；本轮实测模型为 `deepseek-v4-pro` |
| 页面与接口 | 原生 HTML/CSS/JavaScript、FastAPI、uvicorn 单进程 |
| 检索 | scikit-learn 字符 TF-IDF、同义表达归一化、相关度门槛 |
| 数值与单位 | 固定 Python 计算函数、Pint |
| 参数与计划检查 | Pydantic、函数签名及自定义依赖/单位校验 |
| 记录与导出 | 本地 JSON 运行记录、从已有记录生成的 Markdown 报告 |
| 依赖复现 | `pyproject.toml`、`uv.lock`；执行 `uv sync --locked` |

处理流程：输入问题 → 模型核对参数 → 登记计划 → 检索/计算 → 回传工具结果 → 后续调用或结束 → 查看依据与导出。执行器只接受四种登记业务工具；依赖步骤须等待前序成功。

热负荷工具使用 `{"$ref":"s2.value"}` 引用前序流量换算结果。程序解析引用、检查声明依赖和单位、注入实际数值并保存 `input_refs`。若声明依赖质量流量换算却重新抄写数值，执行器拒绝计算。每轮只登记一次计划；工具失败可纠正参数后重试同一步，不支持任意重写计划或断点恢复。

框架适配器将工具结果放进 **`user` 角色的 `Observation` 消息** 再发给模型。核验回传时检查实际请求中的观察内容，而非只查找 `role=tool`。记录省略私密推理及中间助手思考文本。提示要求最终说明先给结论，再给已知条件与适用假设，使用纯文本公式和简单 Markdown；实际调用步骤由工作台展示。

## 3. 状态、补参、取消与会话

| 状态 | 含义与下一步 |
| --- | --- |
| `running` | 当前轮仍在执行，可查看已有步骤并请求取消 |
| `completed` | 已登记步骤全部成功，可查看和导出结果 |
| `needs_input` | 需要用户补充数据；保留上下文后开始关联的新运行 |
| `no_evidence` | 检索依据不足；补充更明确的问题或更新知识资料 |
| `out_of_scope` | 超出当前工具和知识范围，不生成虚构模拟结果 |
| `failed` | 本轮未完成；检查错误信息和成功步骤后重试 |
| `cancelled` | 已停止后续执行，之前完成的步骤可复核 |

补参使用最近最多 8 条用户/助手会话消息；每条进入模型的历史文本最多 6000 字。工作台补参创建新的运行和计划，用 `parent_run_id` 保留前后关联，不复用旧执行器内部结果。CLI 的 `--follow-up` 从指定本地 JSON 记录读取历史；它不是通用断点恢复。

浏览器 Cookie 关联服务内存会话，刷新可恢复当前状态。新任务清空当前上下文，已结束运行可从历史选择查看。每个会话最多保留 40 轮，非活动会话闲置 24 小时后过期。服务使用单进程，同时处理一个模型任务，忙时拒绝新提交并提示重试。重启后界面会话重置，磁盘 `runs/` 记录保留。

取消检查位于任务初始化前后、模型请求返回后以及计划/业务/最终答复工具入口。已发出的 HTTP 请求可能等到返回或超时后才结束，其响应不会继续触发工具。取消发生时已完成的本地步骤保留；请求自身成功和整个任务取消可以同时出现在记录中，二者含义不同。默认单次模型请求超时为 60 秒。

已经启动的工作台会把缺失密钥或任务启动异常转成可导出的失败记录。服务本身无法启动时没有页面记录；磁盘保存失败时界面提示记录警告，当前会话仍可导出内存中的结果。普通模型失败、工具错误和取消按实际记录展示。

## 4. 检索、计算与可证明的边界

检索读取 Markdown/TXT 源文件，按标题/正文排序，并设置最低与相对相关度门槛。无命中返回 `no_evidence`。片段附有 `doc_id`、`chunk_id`、标题、原文、来源和分数；知识版本由文件路径及内容 hash 标识。分数不等于事实正确概率，仍需检查片段是否支持问题。

热负荷按 `Q = m_dot × cp × ΔT` 计算，混合按总质量和目标组分守恒计算。工具检查非有限数值、负流量、非法质量分数、零总流量和不兼容单位；绝对温度与温差分别处理。

`completed` 要求计划全部成功；最终引用只能取自本轮检索片段，有检索依据时须提供引用。最终自由文本未做通用语义和数值一致性校验。界面与报告单独展示**成功工具返回的数值**，保留模型说明及原始参数供核对。

## 5. 报告、追溯与交付包

Markdown 报告只读取已有运行对象，不再次调用模型。内容包含问题、答复、成功工具数值、计划、失败信息、来源摘录及工具适用条件；数值最多显示 12 位有效数字，质量分数使用 0–1 口径。来源正文作有限摘录，完整追溯查看 JSON。失败或未执行调用不会产生成功数值项。

每轮原始记录保存到 `runs/<run_id>.json`，包括历史输入、计划、实际参数、`input_refs`、工具返回、检索资料、状态与请求观察。终态记录可从界面导出 Markdown 和 JSON。Markdown 隐藏本地路径与配置敏感内容；已知密钥会被脱敏，但业务文本仍可能包含敏感信息，分发前须检查。

交付包为 `dist/chem-agent-demo-0.2.0.zip`，使用显式白名单收集源码、页面资源、锁定依赖、配置模板、启动脚本、资料、示例、测试和文档。排除 `.env`、`.venv`、`.local`、缓存和原始 `runs/`。随包验证记录须先核对脱敏；接收方配置自己的模型密钥。完整命令见 [README](../README.md)。
